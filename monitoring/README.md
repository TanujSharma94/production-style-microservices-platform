# Monitoring (kube-prometheus-stack)

Namespace: `monitoring`. Chart version is pinned in `monitoring/CHART_VERSION`.
Lean setup: Alertmanager and node-exporter are disabled, control-plane scrapes that do not work on minikube are disabled.

## Install

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install monitoring prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace \
  --version "$(cat monitoring/CHART_VERSION)" \
  -f monitoring/kube-prometheus-stack-values.yaml \
  --wait --timeout 10m
```

## Project-specific resources

```bash
kubectl apply -f monitoring/ingress-nginx-metrics.yaml   # Service + ServiceMonitor for the ingress controller
kubectl apply -f monitoring/ecommerce-alerts.yaml        # PrometheusRule with 7 alerts
kubectl -n monitoring create configmap ecommerce-dashboard \
  --from-file=monitoring/dashboards/ecommerce-overview.json --dry-run=client -o yaml | kubectl apply -f -
kubectl -n monitoring label configmap ecommerce-dashboard grafana_dashboard=1 --overwrite
```

## Access

```bash
kubectl -n monitoring port-forward svc/monitoring-grafana 3001:80                     # http://localhost:3001 (user: admin)
kubectl -n monitoring port-forward svc/monitoring-kube-prometheus-prometheus 9090:9090 # http://localhost:9090
kubectl -n monitoring get secret monitoring-grafana -o jsonpath="{.data.admin-password}" | base64 -d
```

The Grafana admin password is generated by the chart and is never stored in git.
